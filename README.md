# Wans Teknik — Customer Map

A responsive, admin-only customer map and AC service log built with React, Vite, Leaflet/OpenStreetMap, and Supabase.

## Included
- Email/password admin login; no public sign-up screen
- Supabase Row Level Security policies for admin-only database access
- Customer IDs generated by the database (`WT-0001`, `WT-0002`, ...)
- Separate location IDs (`LOC-0001`, ...), multiple locations per customer supported in schema
- Search by ID, name, phone, address, and landmark
- Interactive map with pins, GPS coordinate picker, and Google Maps navigation
- Service history: date, job type, AC unit count, amount, notes
- Responsive phone/desktop layout
- `.env` excluded from Git by `.gitignore`

## 1. Configure Supabase
1. Open your Supabase project → **SQL Editor**.
2. Run all SQL in `supabase/schema.sql`.
3. Go to **Authentication → Users** and create your owner/admin user with email and a strong password.
4. Assign the user's **app_metadata** claim `{"role":"admin"}` using a trusted admin method. To do this in SQL Editor, copy the user's UUID from Authentication → Users and run the optional UPDATE example at the bottom of `supabase/schema.sql` after replacing `PASTE_ADMIN_USER_UUID_HERE`.
5. Disable public signups in Authentication settings. Create users manually only.
6. Sign out and sign in again after changing app metadata to refresh the JWT.

Authorization is checked by Supabase RLS, not just by hiding UI. Do not put the admin role in `user_metadata`, because users can change that field themselves.

## 2. Configure local environment
Copy `.env.example` to `.env`, then fill values from **Project Settings → API**:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

Only use the publishable/anon key in the browser. **Never use a `service_role` key or secret key in frontend code, GitHub, or committed files.**

## 3. Run locally
Requires Node.js 20+ recommended.

```bash
npm install
npm run dev
npm run build
```

## 4. Publish on GitHub Pages
1. Upload/push these project files to your GitHub repository (keep `.env` private and do not upload customer data).
2. GitHub repository → **Settings → Secrets and variables → Actions**. Add repository secrets:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. Repository **Settings → Pages** → select **GitHub Actions** as source.
4. The included `.github/workflows/deploy.yml` builds and deploys on pushes to `main`.
5. Open the Pages URL after the workflow succeeds.

If deploying under `username.github.io/repository-name/`, change `base: './'` in `vite.config.ts` to `base: '/repository-name/'` if the asset paths need it.

## Privacy and production checklist
- Code can be public, but customer records must remain only in Supabase.
- Never commit `.env`, customer exports, access tokens, or customer screenshots.
- Test using a non-admin account and confirm it cannot read or change any customer tables.
- Back up Supabase regularly and test restoration.
- OpenStreetMap provides public map tiles. The app loads customer coordinates only after sign-in; RLS enforces authorization.
- This is a starter build, not yet connected to your Supabase project. Test it before entering real customer data.
